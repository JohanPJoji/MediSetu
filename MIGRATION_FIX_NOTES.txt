MediSetu migration fix
======================

Fixed the PostgreSQL ENUM migration handling so Alembic does not attempt to
CREATE TYPE twice when an enum has already been created.

Affected migration revisions:
- be3ca5bc0dde  user_role
- a823fb84d48f  patient_sex
- 5e6c7d8f9a0b  consultation_status
- 6f7d8e9f0a1b  transcript_role
- 8b9c0d1e2f3a  prescription_status, referral_status
- 9d1e2f3a4b5c  pharmacy_order_status, inventory_transaction_type

The migrations now explicitly create each enum with checkfirst=True and use
create_type=False for the same enum when the table is created.

From backend/, run:

  ..\\.venv\\Scripts\\python.exe -m alembic -c alembic.ini current
  ..\\.venv\\Scripts\\python.exe -m alembic -c alembic.ini upgrade head

Do NOT delete the PostgreSQL enum types manually before trying this.

Runtime-test hardening pass (2026-09-15)
========================================

Fixed an API router registration bug that mounted the patient router under
/api/patients/patients instead of /api/patients.

Updated patient/consultation test fixtures so privileged users (DOCTOR,
ADMIN) are created directly in the test database. This preserves the
production security rule that public registration is PATIENT-only while still
allowing privileged workflow tests to exercise their authorized behavior.

Updated the patient lookup test to create and assign a real consultation
before asserting that a doctor can access that patient's record, matching the
implemented resource-level authorization rule.

The supplied 49-test run had 26 failures. Those failures were traced to the
patient-router double-prefix (causing the large cluster of 404s), plus test
fixtures attempting forbidden public signup for privileged roles, and one
patient-doctor authorization setup mismatch.

Integration pass (2026-09-15)
=============================
Added UUID-native integrations derived from hospital-backend.zip without replacing
MediSetu's existing authentication, patients, consultations, prescriptions,
medicines, pharmacy, referrals, documents, or timeline implementations.

New backend areas:
- Laboratory tests, orders, results and verification
- Billing, bill items, payments and payment status
- Inventory batches and inventory transactions with medicine stock updates
- Medicine shortage alerts and alternative medicines

New Alembic head: a1b2c3d4e5f6

Added a lightweight React/Vite frontend for smoke/demo use. The frontend uses
same-origin /api calls so Vite proxies them to the FastAPI backend in development.
Demo accounts use the valid .dev domain used by Pydantic EmailStr.

The demo seed is now idempotent with respect to the fixed DEMO-DR-001 registration
number when an existing doctor record is already present.

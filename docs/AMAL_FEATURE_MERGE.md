# Amal Jyothi Feature Merge

This merge keeps MediSetu's existing UUID/PostgreSQL/RBAC architecture and adds the parts of the Amal Jyothi project that were missing without introducing a second authentication or database stack.

## Added features

### Local voice transcription
- Browser `MediaRecorder` captures `audio/webm`.
- `POST /api/consultations/{consultation_id}/voice-input` transcribes locally with `faster-whisper`.
- Supported input MIME types are configurable through `ACCEPTED_AUDIO_FORMATS`.
- Audio size is limited by `MAX_AUDIO_SIZE_MB`.
- Whisper confidence is converted to a 0–1 score and compared with `STT_MIN_CONFIDENCE`.
- Low-confidence audio is rejected from AI follow-up processing and returns a retry message.
- The transcript is stored in MediSetu's existing `transcript_entries` table.

### Conversational follow-up questions
- `POST /api/consultations/{consultation_id}/follow-up` generates the next focused intake question.
- The existing `/process-intake` path continues returning `follow_up_questions`.
- An optional OpenAI-compatible/Omni Router provider can produce richer questions.
- Without an external provider, the existing deterministic MediSetu logic remains the fallback.

### Doctor-facing summaries
- `GET /api/consultations/{consultation_id}/summary` is restricted to doctor/nurse/admin roles.
- The endpoint returns a concise summary, key points, the structured clinical history and remaining follow-up questions.
- It does not alter the stored consultation or clinical history.

### Optional local text-to-speech
- Voice responses can be converted to audio with Windows `pyttsx3`/SAPI5 when available.
- TTS is best-effort and never makes the transcription or clinical workflow fail.

### Deterministic safety checks
- Emergency/red-flag patterns from the Amal project were adapted into `app/services/safety_service.py`.
- Voice input checks these patterns before optional LLM follow-up generation.
- Emergency responses are fixed text and are not generated by the LLM.

## What was intentionally NOT copied

The Amal project had a separate SQLite/SQLAlchemy schema, its own authentication, doctor/patient tables, intake sessions, case reports and audit models. Those overlap with MediSetu's existing PostgreSQL UUID/RBAC/consultation/clinical-history architecture, so they were not copied. Reusing both stacks would create duplicate sources of truth and increase regression risk.

The feature behavior was instead adapted onto MediSetu's existing consultation, transcript and clinical-history entities.

## New endpoints

- `POST /api/consultations/{consultation_id}/voice-input`
- `POST /api/consultations/{consultation_id}/follow-up`
- `GET /api/consultations/{consultation_id}/summary`

The existing `POST /api/consultations/{consultation_id}/audio` endpoint remains available for backwards compatibility and now uses the local STT service as configured.

## Optional external AI

Set these only when an OpenAI-compatible provider is intentionally enabled:

```env
LLM_PROVIDER=omnirouter
LLM_API_KEY=...
LLM_BASE_URL=https://api.omnirouter.ru/v1
LLM_MODEL=gpt-4o-mini
```

Leaving these variables unset preserves the deterministic local behavior that was already used by MediSetu's automated tests.
